## Предположение

Каждый массив займет около 8 МБ. Память всего процесса не будет равна этому объему.

## Наблюдение

На начальной паузе Pra05 в Диспетчере задач занимает памяти: 2,8 МБ

Память в Диспетчере задач после четвёртого шага: 33,4 МБ
## Результат
1. Расчётный объём увеличивался  равномерно. На каждом шаге создавался новый массив, поэтому к общему объёму каждый раз прибавлялось ровно по 7,63 MiB.
2. Нет, не одинаково. Прирост рабочего набора скакал от шага к шагу.
3. На шаге 0 процесс использует память (15,16 MiB) для: .NET, JIT-компилятора, системных библиотек. На шаге 4: объём самих элементов составляет 30,52 MiB, а рабочий набор процесса — 48,80 MiB. Рабочий набор больше, потому что он включает в себя не только сами данные массивов, но и ту самую память среды выполнения (которая была на шаге 0).
4. Для нашего опыта лучше подходит Pra05. Общая занятая RAM компьютера — это неинформативный показатель для эксперимента, так как на неё влияет множество посторонних факторов. Кроме наших массивов, на общую RAM влияют: операционная система, фоновые службы Windows, другие запущенные программы, кэш файловой системы. Из-за этого невозможно точно определить, сколько памяти заняли именно наши массивы.
## Эксперимент 2. То же количество элементов, другой тип
## Предположение 
Так как int занимает 4 байта, то расчетный объем увеличится в 4 раза.
## Наблюдение 
| Шаг       | Кол-во массивов | Расчётный объём (MiB) | Рабочий набор (MiB) | Изменение от начала (MiB) |
   | :-------- | :-------------- | :-------------------- | :------------------ | :------------------------ |
   | 0 (Старт) | 0               | 0                     | 14,70              | 0                         |
   | 1         | 1               | 30,52                  | 47, 52              | 32,83                      |
   | 2         | 2               | 61,04                 | 78,47               | 63,78                     |
   | 3         | 3               | 91,55                 | 109,33               | 94,64                    |
   | 4         | 4               | 122,07                 | 139,95               | 125,25                    |

2. При сравнении результатов видно, что при использовании типа int расчётный объём данных на каждом шаге ровно в 4 раза больше, чем при использовании byte. 

3. Отношение расчётных объёмов (на 4 шаге):
Расчётный объём для int (122,07 MiB) / Расчётный объём для byte (30,52 MiB) = ровно 4.0.

Отношение изменений рабочего набора (на 4 шаге):
Изменение для int: 125,25 MiB.
Изменение для byte: 33,64 MiB.
Отношение: 125,25 / 33,64 ≈ 3.72.

Вывод: Отношения не совпали точно.

4. Пример из таблиц (Шаг 1):

· Для byte: Объём данных = 7,63 MiB. Рабочий набор вырос с 15,16 до 25,11 MiB, то есть прирост составил 9,95 MiB. Разница между приростом и данными (9,95 - 7,63 = 2,32 MiB) — это накладные расходы.
· Для int: Объём данных = 30,52 MiB. Рабочий набор вырос с 14,70 до 47,42 MiB, то есть прирост составил 32,72 MiB. Разница (32,72 - 30,52 = 2,20 MiB) — это те же самые накладные расходы.
## Эксперимент 3. Влияет ли значение числа на размер данных
## Предположение
Нет, всегда занимает 4 байта, не зависимого от того хранить ли число 1 или 1 000 000.

| Шаг       | Кол-во массивов | Расчётный объём (MiB) | Рабочий набор (MiB) | Изменение от начала (MiB) |
   | :-------- | :-------------- | :-------------------- | :------------------ | :------------------------ |
   | 0 (Старт) | 0               | 0                     | 14,70              | 0                         |
   | 1         | 1               | 30,52                  | 47, 54              | 32,84                     |
   | 2         | 2               | 61,04                 | 78,49               | 63,79                   |
   | 3         | 3               | 91,55                 | 109,35               | 94,65                   |
   | 4         | 4               | 122,07                 | 139,97               | 125,26                    |

2. Разница составила в рабочем наборе 0,01 MiB.
3. Программа вывела контрольную сумму 4 000 000.
4. Шаг 4: рабочий набор составил маленькую разницу. 
5. Нет, таких оснований. 4 шаг: 
Для 1: Объём элементов = 122,07 MiB, Рабочий набор = 139,95 MiB.
Для 1 000 000: Объём элементов = 122,07 MiB, Рабочий набор = 139,96 MiB.
Любая микроскопическая разница в показаниях связана с работой операционной системы, а не с тем, какое именно число записано в ячейку памяти.
## Результат 
1. Только тип (он имеет фиксированный размер в байтах) и количество элементов. Цифры в числе на это не влияют.

2. Почему расчет совпадает, а измерения различаются?
Расчет — это чистая математика. А реальные измерения «плавают» из-за накладных расходов: работы среды .NET, сборщика мусора.
