## Практическая работа №5. Оперативная память: куда попадают данные программы

## Эксперимент 1. Накапливаем данные по шагам

## Предположение

Каждый массив займет около 8 МБ. Память всего процесса не будет равна этому объему.

## Наблюдение

На начальной паузе Prac05 в Диспетчере задач занимает памяти: 2,8 МБ
| Шаг       | Кол-во массивов | Расчётный объём (MiB) | Рабочий набор (MiB) | Изменение от начала (MiB) |
   | :-------- | :-------------- | :-------------------- | :------------------ | :------------------------ |
   | 0 (Старт) | 0               | 0                     | 15,16               | 0                         |
   | 1         | 1               | 7,63                  | 25,11               | 9,95                      |
   | 2         | 2               | 15,26                 | 33,03               | 17,86                     |
   | 3         | 3               | 22,89                 | 41,07               | 25,91                     |
   | 4         | 4               | 30,52                 | 48,80               | 33,64                     |

Память в Диспетчере задач после четвёртого шага: 33,4 МБ
## Результат
1. Расчётный объём увеличивался  равномерно. На каждом шаге создавался новый массив, поэтому к общему объёму каждый раз прибавлялось ровно по 7,63 MiB.
2. Нет, не одинаково. Прирост рабочего набора скакал от шага к шагу.
3. На шаге 0 процесс использует память (15,16 MiB) для: .NET, JIT-компилятора, системных библиотек. На шаге 4: объём самих элементов составляет 30,52 MiB, а рабочий набор процесса — 48,80 MiB. Рабочий набор больше, потому что он включает в себя не только сами данные массивов, но и ту самую память среды выполнения (которая была на шаге 0).
4. Для нашего опыта лучше подходит Prac05. Общая занятая RAM компьютера — это неинформативный показатель для эксперимента, так как на неё влияет множество посторонних факторов. Кроме наших массивов, на общую RAM влияют: операционная система, фоновые службы Windows, другие запущенные программы, кэш файловой системы. Из-за этого невозможно точно определить, сколько памяти заняли именно наши массивы.
